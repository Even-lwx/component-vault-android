# 元件仓 · Component Vault

个人电子元器件库存 Android App，最低支持 Android 8.0（API 26）。

库存卡片、详情及录入表单按“类别 → 阻值 / 容值 / 感值和颜色 → 封装 → 电压、功率、电流 → 型号和采购信息”的顺序展示。颜色、电压、功率及电流支持识别、候选核对、手动录入、详情更正、搜索与导出。未知参数保持空白，不根据型号推测。电压字段可能表示工作电压或耐压，需对照标签核对。

## 首版范围

- **扫一扫**：相机连续运行中文 OCR、英文字母 / 数字 OCR 与条码识别，聚合多帧字段候选；无论识别成功或失败都不会自动结束。先移开标签，再点完成并确认后才进入核对页。支持预览对焦、变焦和补光灯。
- **高清补识别**：在扫码页拍摄高画质标签照片，再由中英文模型与条码模型复核并合并结果。数字、字母有分歧时列出候选，用户可以对照原图选择或手动改正；系统不把 `O/0`、`I/1`、`S/5` 盲目互换。
- **分类**：优先使用标签上印出的具体类别，保留“发光二极管/LED”“快恢复/高效率二极管”等名称，而不把它们降成宽泛的 LED / 二极管。标签标题末尾的 `...`、`…`、`⋯` 若只匹配一个已知或用户自定义类别，会补全完整名称；存在歧义时保留提示，让用户手动核对。旧库存的一般类别会根据已保存的标签文字升级细分。用户仍可在分类管理中新增、改名、删除类别。
- **拍照 / 相册**：用中英文两种 OCR 模型识别整张标签与二维码，提取型号、物料编码、平台、封装、品牌、分类和数量候选值。
- **主要参数**：独立提取并保存阻值、容值和感值；支持 `10kΩ`、`100nF`、`4.7uH`、中文单位，以及有物料类型上下文的 `4K7`、`2R2`、`4R7`（电感）等写法。三个字段直接显示在核对页、详情及库存卡片，可选择候选或手动更正。等价单位会归一化，例如 `0.1uF` 显示为 `100 nF`。
- **手动入库**：填写平台 / 供应商、物料编码、型号、品牌、封装、分类、规格、实际数量、存放位置和备注。
- **库存查询**：按分类筛选，按平台、型号、编码、品牌、封装、位置、规格和备注搜索。
- **出入库流水**：领用、补货及用途记录。库存和流水在 SQLite 同一事务中提交，禁止负库存。
- **重复物料**：有编码时按编码识别；没有编码时按型号、封装、品牌与主要参数组合识别。同一物料、同一存放位置提示补货；不同位置或不同主要参数分别记录。
- **数据导出**：CSV 库存清单；JSON 库存及完整流水。照片保存在应用私有目录，导出文件不包含照片。

库存保存在手机本地，扫码 / OCR 支持离线使用；点击立创查询时需要联网。尚未包含服务端、电脑网页后台、账号同步和导入恢复。

## 安装与构建

当前版本为 0.14.0。用 Android Studio 打开本目录，等待 Gradle 同步完成后运行 `app`。

0.14.0 首页优化：缩短扫码区域，将拍照、手动录入和 BOM 配料排列成快捷入口，库存卡片突出类别与参数，数量使用状态色区分（0 为用尽，1～10 为低库存）。初次显示 80 条，可以继续加载，避免一次创建大量卡片。

分类标签显示“类别 · N种”。种数按完整商品编号去重，无编号时按型号、品牌、封装、主要参数、颜色和电气额定值组合去重；同种物料不同库位只计一种，用尽记录仍计入已建档种数。默认按种数从多到少排序，同数按中文名称排序；长按可置顶，置顶始终最先。分类设置中可改名称排序或最近访问优先，也可显示 / 隐藏空类别。最近访问仅在主动点击类别时记录。种数为全库计数，不受当前搜索和筛选影响。

库存排序支持最新录入、数量升 / 降序、类别、型号、主要参数数值升序。参数数值分别按电阻、电容、电感排序，同类按 SI 换算后的数值比较，未知值在后。组合筛选支持库存状态、封装、颜色和位置，所有条件须同时满足；筛选与排序会在本机记忆，空结果可一键重置。多关键词以空格分隔并同时匹配，例如 `0.1uF 0402`；容值等支持等价单位查询。

0.13.0 修复“已找到编号，正在读取商品详情参数”停留问题：从主页面开始加载时就读取 DOM，不再依赖所有图片 / 统计资源加载结束。参数表按单元格读取，支持移动端折叠 / 视口外内容。整次查询截止时间为 60 秒，页面导航不会反复延长；脚本超过 4 秒未返回则重试并忽略过期回调。超时明确展示最近失败原因，允许继续读取、重新查询或返回手动录入。登录等待单独暂停，登录返回后重新计时。

0.12.0 的「扫一扫」是独立二维码流程：相机只解码二维码 / 条码，不初始化或运行 OCR。取得唯一立创物料编号后，立即自动查询商城；商品编号一致且参数加载完成时直接进入录入表单，不再要求移开标签或二次采用商城资料。商品属性全部使用商城返回内容，缺失留空，不用 OCR 补猜；数量可使用二维码原包装数量作候选，实际数量和位置仍需用户核对，确认入库前不改变库存。联网失败 / 登录验证无法完成时可返回或明确选择手动填写。拍照 / 相册仍为单独的 OCR 入口。

开发环境：JDK 17、Android SDK Platform 36、Gradle 8.7、Android Gradle Plugin 8.6.0。使用已安装的 SDK 36 编译；该版 AGP 对 SDK 36 会产生兼容性提示。

首次构建需要联网下载依赖。当前网络无法直连 Google Maven，因此项目优先使用阿里云 Google Maven 镜像，并保留官方源。扫码与中文识别采用随应用打包的 ML Kit 模型，运行时无需下载模型，也不需要将照片上传到服务端。

Windows 命令：

```powershell
./gradlew.bat assembleDebug testDebugUnitTest lintDebug
```

调试安装包生成位置：`app/build/outputs/apk/debug/app-debug.apk`。

`local.properties` 是本机 SDK 路径，请按实际环境调整；不要将该文件作为共享配置。

## 使用示例

### BOM 导入与库存匹配（离线可用）

1. 首页点击「BOM 导入 · 套数配料 · 缺料匹配」，选择 CSV / TSV / XLSX 文件；工作簿可选择工作表及表头行。
2. 将 BOM 的位号、每套数量、参数值、封装等列对应到界面字段。必须指定每套数量列，无法解析的数量会标红并要求修改，不会悄悄按 1 个计算。
3. 输入要做的套数，选择匹配条件，点击重新匹配。默认阻值 / 容值 / 感值和封装都必须匹配；也可按编号、型号、颜色、类别、电压、功率、电流精确匹配。若选中条件缺失，该行不会自动匹配，需编辑 / 补齐或改选条件。
4. 查看每行的总需求、可分配数量、缺料数量及对应库存位置。所有行共享同一份剩余库存，相同物料分放多个位置可合计分配；按 BOM 行顺序试算，不扣减实际库存。
5. 点击修改此行可以调整位号、用量、参数等；点击选择库存可更换匹配或人工指定替代物料。不符合条件的人工替代需要额外确认，所选匹配条件不等于电气兼容性保证。精度、温度特性、极性及其他设计要求需要自己核对。
6. 导出 CSV 或 XLSX。保留源表格的原始列，在其后明确附加修改后的参数 / 数量、套数、需求、匹配编号、位置分配和缺料列。XLSX 导出为新结果表，不保留原工作簿样式、图片、公式及其他工作表。

常见 `Value` / `Comment` 及中英文数量、位号、封装标题可自动建议对应列。`0.1uF` 与 `100nF` 可按归一化后的值匹配。只有位号 / 类型能明确 R/C/L 时才解释 `10K`、`100n` 等省略单位写法。封装采用精确文本匹配，不把 `R_0603_1608Metric` 与 `0603` 或英制 / 公制名称直接当作相同，必要时在编辑行中统一。

### 从微信 / 钉钉附件导入

打开聊天附件的菜单，选择「分享 / 用其他应用打开」，再选择「元件仓 BOM」。只要聊天应用授予文件内容读取权限，就可以直接导入，无须你先另存到下载目录。也可在 App 的系统文件选择器中选择它提供的文件。

应用不能直接读取其他软件的聊天记录或私有附件目录。如果对应版本的微信 / 钉钉没有开放文件分享或系统文件提供器，只能先通过它提供的保存 / 分享入口取出附件。聊天软件可能需要先从网络下载附件内容；这与 BOM 匹配本身的离线能力无关。

文件范围：CSV（UTF-8 / GB18030 / UTF-16）、TSV、XLSX。旧版 XLS 暂不支持，需另存为 XLSX / CSV。一次分析一个工作表，最多 10000 行、100 列，输入文件最多 20MB；公式只读取已保存的缓存值，不执行公式，缺缓存时要求重新计算并保存。当前 BOM 会在应用私有缓存保留供页面重建，不是长期项目保存；请及时导出。

推荐流程：完成标签扫描取得二维码中的完整立创编号 → 有网且开启自动查询时自动打开商城搜索 → 自动定位编号一致的商品详情并等待参数表 → 核对并「采用商城资料」→ 填写实际数量和位置入库。保留核对页「按物料编号查询立创参数」和详情页「按编号联网校准立创参数」入口。自动查询不跳过扫描结束确认，不自动入库；在核对表单中可关闭自动查询，断网则保留离线结果。

商城搜索 / 详情会自动尝试读取一段有限时间，找不到唯一结果、网页未加载或要求验证时会停止并提示。已观察到立创把部分搜索重定向到 `passport.jlc.com` 官方登录页；此时需用户自行登录，返回商城后才继续。没有匿名访问必定成功的保证，没有接入官方 API 凭据，也不绕过登录或验证码。

照片处理：按 EXIF 方向校正显示，限制解码尺寸；先识别原图。若二维码没有可用商品编号，再尝试基于初次识别文字框的区域裁剪、适度放大及轻度灰度对比增强。原图结果保留，新增结果进入候选分歧，不强制覆盖。不做强二值化、自动透视矫正或去模糊；首轮没有检出文字时使用整图增强，因此不等于可靠的标签边界检测。实时相机帧仍使用原画面，高清补拍与拍照 / 相册共用该处理流程。

真实标签二维码已解码验证：`pc` 是物料编号，`pm` 是型号，`qty` 是原包装数量。例如 C489136 对应 FR107(RS1M)，C25503345 对应 XL-1005SURC。这两张二维码没有电容 / 电阻参数，需要用编号查询商品资料。二维码明确提供的字段优先于 OCR，同时保留来源与分歧。

联网查询采用可见官方商品页面，不依赖未授权内部接口，也没有内置 API 密钥。商城页面可能要求登录 / 验证或因网络不可用而加载失败；可在页面自行处理或返回手动录入。官方 LCSC API 需要申请，本版没有接入该 API。当前解析已验证公开商品详情页结构，页面改版可能需要适配。WebView 自身可能保存会话 cookie；应用不抓取或另存登录表单和密码。

查询严格校验当前商品编号，并按属性名读取阻值、容值、感值、颜色、封装、电压、功率、电流；不会读取推荐商品或把“漏电流 / 浪涌电流”当成额定电流。正向压降和范围参数按原属性保留在规格说明，不当作耐压。商城库存和起订量不会覆盖实际库存。`10.2` 与 `102.2` 有分歧时须核对；商城结果可用于更正，单凭 OCR 不会猜正确值。

1. 点击「拍照 / 相册」，完整拍下物料袋标签，尽量避免反光和模糊。
2. 核对识别结果。例如 `C489136 / FR107(RS1M) / DO-214AC(SMA)`。
3. 将数量改为**实际剩余数量**，填写位置，例如 `A柜 / 03格`，然后确认入库。
4. 点击库存条目，进行领用或补货，并查看流水。
5. 点击首页「导出」，将清单保存到自己选择的位置。

分类维护：点击首页「管理分类」，选择分类可改名或删除，点击「＋ 新增分类」可创建自己的类别。录入表单也提供“选择分类 / 管理分类”。已有库存可在详情中点击「更改物料分类」。删除时需选择转移目标并确认；不会删除该分类下的物料或流水。分类是单选属性，当前没有多标签同时挂载功能。

删除误录物料：打开库存条目，在详情底部点击「删除物料及全部出入库记录」，确认物料名称和当前数量后再执行。删除会清掉该条物料、相关流水及关联标签照片；该操作无法撤销。若只是录错数量，请从详情执行领用或补货调整数量，不要删除整个物料。

对于字母数字混淆：扫码时点击文字区域对焦，必要时用变焦或「高清拍照补识别」。进入核对表单后，出现“识别有分歧”可展开选择其他实测候选。仍有错误可以直接修改输入框，保存前应与原图对照。

主要参数：不需要把参数藏在“规格参数”中。阻值、容值和感值有单独输入框，适用项可直接填写，例如阻值 `10K`、容值 `0.1uF`、感值 `4.7uH`。没有型号 / 编码也能按主要参数建档。已有物料可从详情中的「补录 / 更正阻值、容值、感值」修改，不影响数量和流水。搜索 `0.1uF` 也能查到归一化后的 `100 nF`。

类别标题若被 OCR 显示成 `快恢复/高效率二...`，系统按内置类别或你的自定义类别做唯一前缀匹配并补齐。前缀匹配到多个类别时会要求选择，不会把带省略号的名字当作正式类别存入库存。

## 识别与数据边界

- 二维码内容没有统一标准，可能只有编码、订单号或网址。未知格式保留原文，缺失字段由用户补充；应用不会自动访问二维码中的网址。
- 内置解析器支持常见标签文字、部分 JSON / 键值格式，不代表已适配所有供应商标签。截图对应的两个标签以文字转录作为解析测试样例，尚不能据此宣称实拍识别通过。
- 原包装 `QTY` 不等于当前剩余数量，所有入库都需要人工核对。
- 主要参数解析依赖 OCR 实际读到的数值与单位；如果照片中的字符没读出，这一版不会凭型号或供应商编码猜出参数。裸 `104`、`103` 既可能是标码也可能是其他数字，暂不在没有明确上下文的情况下自动解码。`mΩ` 与 `MΩ` 保持 SI 大小写含义，不能盲目互换。
- 实时读取不会因首次检出条码或识别器短暂漏读而结束。用户移开标签后手动完成，再进入核对。两个 OCR 模型同帧结果不重复计票，分歧会保留为型号候选；不自动做数字 / 字母混淆替换。要读小字，请点击文字对焦、调整变焦，或用“高清拍照补识别”。首版没有实拍准确率基准，仍应对照标签核对。
- 库存统计的「种」按物料与存放位置的库存条目计算。同一物料分放两个位置会计为两条。
- 卸载应用会清除本地数据。CSV / JSON 导出不等于可一键恢复的完整备份，本版尚无导入功能。
- 调试包适合个人试用，正式发布前应配置发行签名并在目标手机验证相机、照片识别、权限、导出及不同屏幕显示。

## 代码结构

```text
app/src/main/java/cn/componentvault/app/
  MainActivity.java      库存界面、核对表单、照片识别和导出
  ScanActivity.java      相机实时扫码
  LabelParser.java       不依赖 Android 的标签候选信息解析
  ScanSession.java       连续帧候选投票
  OcrCandidates.java     保留有分歧的字段候选供人工选择
  PassiveValues.java     阻值、容值、感值的单位解析与归一化
  InventoryStore.java    SQLite 库存和出入库事务
  Part.java              物料数据
app/src/test/            标签解析单元测试
```

实现采用原生 Java 与 Android 控件，避免引入额外跨端框架；识别解析、数据存储、相机扫码和分类维护各自承担单一职责。当前库存闭环仅保存于手机本地。
